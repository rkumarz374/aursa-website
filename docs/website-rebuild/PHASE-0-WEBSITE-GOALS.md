## 1. Company & Website Context

AURSA operates across two connected products and use cases under a single unified brand ecosystem.

### AURSA Retail (B2B)
* **Context & Moment:** Supports fashion retailers at the shopper trial-room decision moment.
* **Core Shopper Question:** *“Does this actually work for me?”*
* **Usage Scenario:** Takes place immediately after a shopper has tried an outfit in a store fitting room but feels uncertain whether to purchase it.
* **Value Proposition:** Provides the shopper with a private, personalized second opinion inside the fitting room.
* **Commercial Objective:** Secure fashion retailer commitments to run an AURSA retail pilot.
* **Primary Commercial CTA:** `"Request a Retail Pilot"`

### AURSA Personal (B2C)
* **Context & Moment:** Live consumer app supporting individuals in their personal environment.
* **Core Consumer Question:** *“Does this actually work for me?”*
* **Usage Scenario:** Takes place before stepping out, when the user looks in their home mirror and hesitates.
* **Value Proposition:** Delivers a private second opinion to help the user understand their outfit and step out with confidence.
* **Primary Consumer CTA:** `"Download / Try AURSA"`

## 4. Website Experience Principle

> **CORE PRINCIPLE: "Simple on the surface. Intelligent underneath."**

1. **No Excessive Complexity:** The website must not attempt to prove technical intelligence through cluttered widgets, noisy data overlays, or dense tech jargon.
2. **Intelligence Through Craft:** Intelligence must be demonstrated through:
   * Radical clarity of message and storytelling.
   * Meaningful, deliberate interactive elements.
   * Seamless contextual transitions between contexts.
   * Thoughtful, smooth motion and pacing.
   * True-to-life representation of the trial-room and mirror moments.
3. **Purposeful Animation Rules:** Every micro-interaction and motion element must convey specific meaning:
   * *Mirror environment transition* = Context shifts between Retail and Consumer.
   * *QR code appearance* = Decision support becomes instantly available in the trial room.
   * *Phone interface emergence* = AURSA active guidance enters the decision moment.
   * *Retail $\rightarrow$ Consumer toggle* = Demonstrates the same human problem solved across two environments.
   * *Decorative, non-functional animations are strictly prohibited.*

## 6. Strict Exclusion List — What We WILL NOT Show

To protect proprietary intellectual property and maintain brand positioning, the website **MUST NEVER** expose internal machinery or technical implementation details.

### Excluded Technical Content:
* Internal AI system architecture or model provider dependencies (e.g., specific LLM/VLM vendors).
* Scoring algorithms, proprietary weights, or internal evaluation metrics.
* Internal engine terminology (e.g., *Observation Layer*, *Style Profile internals*, *Style Intelligence Engine internals*, *Style Identity Engine internals*).
* Backend system architecture, APIs, data schemas, or database structures.
* Internal prompt engineering logic or system prompts.
* Proprietary reasoning formulas or scoring equations.
* Infrastructure specs, cloud setup, or low-level technical stack details.

*Rule:* **Communicate human and business outcomes, never internal machinery.**

## 7. Privacy Principle

Privacy is a non-negotiable pillar of user and enterprise trust.

### Core Public Privacy Message:
> **"AURSA analyzes the outfit image solely to deliver the real-time experience. AURSA does not store the user's outfit photo."**

### Privacy Communication Directives:
* **Simple:** Free from legalese or confusing technical jargon.
* **Prominent:** Clearly accessible across key user touchpoints.
* **Understandable & Reassuring:** Instantly instills confidence in consumers and retailers alike.
* **Factual:** Never make privacy claims that exceed current system capabilities.

## 13. Performance & Quality Principles

Future interactive elements must adhere to strict performance budgets:
* **Immediate Hero Rendering:** First Contentful Paint (FCP) and Largest Contentful Paint (LCP) prioritized.
* **Lightweight Motion:** Prefer the simplest performant technique appropriate to the interaction. Motion must not compromise SEO, accessibility, page performance, or Core Web Vitals.
* **Mobile-First Quality:** Preserve the same core meaning, capability, privacy communication, and conversion paths across mobile and desktop while allowing interaction patterns to adapt appropriately to each device.
* **Lazy Loading:** Non-critical visual assets and interactive widgets deferred.
* **Accessibility:** Full WCAG AA compliance, semantic markup, and `prefers-reduced-motion` support.

## 15. Non-Negotiable Implementation Rules for Future Phases

Every future implementation phase (Phase 1+) MUST strictly follow these rules:

1. **Audit First:** Audit relevant existing code before making any edits.
2. **Identify Impact:** Explicitly list affected files prior to modification.
3. **Preserve Functionality:** Preserve all existing unrelated functionality.
4. **API Stability:** Do not modify API signatures or endpoints unless explicitly authorized.
5. **App Logic Stability:** Avoid modifying app product logic.
6. **Backend Stability:** Do not alter backend functionality unless explicitly required.
7. **No Speculative Edits:** Strictly avoid speculative refactoring or unrequested enhancements.
8. **Scoped Execution:** Keep changes strictly within the defined phase scope.
9. **Responsive Validation:** Validate on both mobile and desktop viewports.
10. **Route Verification:** Verify all existing routes remain functional.
11. **Build Success:** Verify build compilation (`npm run build`) succeeds cleanly with 0 errors.
12. **Transparent Audit:** Document all changed files in the final task output.
13. **Risk Disclosure:** Explicitly call out any technical risks or assumptions.
14. **Immediate Stop:** Immediately stop and notify if a requested change requires breaking unrelated product logic.
